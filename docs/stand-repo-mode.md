# Стенд в режиме приложения

Стенд умеет проверять не локальную сборку, а сам репозиторий — так же, как это делает Aniyomi.

## Запуск

```bash
cd /home/work
python3 tools/audit_anime.py --from-index --lang any --nsfw --batch 4 --out /tmp/audit_final.json
python3 tools/audit_report.py /tmp/audit_final.json
```

| Ключ | Что делает |
|---|---|
| `--from-index` | берёт APK не из `apk/` репозитория на диске, а из `index.min.json` по ссылке |
| `--index URL` | адрес индекса (по умолчанию raw.githubusercontent…/main/index.min.json) |
| `--lang ru\|all\|any` | какие расширения брать |
| `--nsfw` | включать NSFW |
| `--no-retry` | без повторного прохода по сетевым сбоям |

## Как это повторяет приложение

1. Читается `index.min.json` — тот же файл, что видит клиент.
2. Из записи берутся `pkg`, `apk`, `code`, `version`.
3. APK качается по `<база индекса>/apk/<apk>`, проверяется, что это zip с `classes.dex`.
4. Файл загружается в приложение через `DexClassLoader` (форк не ставит расширения пакетами, поэтому `pm install`/`dumpsys` не используются).
5. Источник инстанцируется по FQCN, прогоняются шаги: каталог → страница 2 → детали → постер → серии → порядок → видео.
6. Модули с сетевым сбоем повторяются один раз (SSL, таймаут, обрыв) — сеть на VPS нестабильна.

## Что проверяется

| Шаг | Смысл |
|---|---|
| `catalog` | список непустой, есть названия |
| `page2` | вторая страница отдаёт столько же |
| `details` | заголовок, описание, жанры |
| `thumb` | постер реально скачивается (200 + image/*) |
| `episodes` | список серий непустой |
| `order` | порядок серий не «хаос» (дубли/перемешанные номера) |
| `video` | плеер отдаёт ссылки |

## Классификация сбоев

`audit_report.py` делит причины, чтобы не путать баг расширения с окружением:

- **парсинг** — страница не разобралась (наш баг);
- **сайт** — 403/404/5xx, пустой ответ (источник сломался);
- **сеть** — SSL, таймаут, обрыв (IP/блокировка, не код);
- **стенд** — NPE корутин, класс не найден (ошибка инструмента).

Первый сбойный шаг считается причиной, остальные падения ниже по цепочке попадают в «каскад».

Отчёт складывается в `/home/work/reports/audit-YYYY-MM-DD.md`.
